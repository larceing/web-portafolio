Own product · running · 2026

Ada: marketing for my channels with n8n and AI

Problem
Running YouTube, Instagram, TikTok and LinkedIn with videos, covers and copy every day eats up the evenings, and the day something breaks, nothing gets published.
What I did
Ada, a system in n8n that works in two cycles. Every week it asks ChatGPT for the stories and prepares episodes, reels, posts and campaigns; every night it looks back at the day and, if it is worth it, prepares a news video. ChatGPT writes the stories and makes the images, Google AI Studio does the voices, and editing, clips and covers come from my own video engine. Everything goes into a queue: the evening before, at 8 pm, it checks cover, copy, time, a maximum of three posts a day per network and no repeated topic within 14 days, and sends an email with a “Stop” button for each post.
Result
Approved posts go out through Buffer and the YouTube API, and the video is archived on its own. An error and alert log: if the image or voice quota runs out, it records the time and picks the work up again when there is quota; if a network fails, it asks for a manual upload. Review and alerts are live; automatic publishing is in testing.

n8n · OpenAI API · Google AI Studio · Buffer · YouTube API · rclone

Own product · part of Sindri · 2026

Efesto: Sindri reads the factory

Problem
Machine status, good and bad parts and alarms stay inside each PLC or SCADA, far from the ERP, and connecting them usually means opening ports into the factory.
What I did
A read-only shop-floor agent with 16 connectors: OPC UA, Modbus, Siemens S7, Rockwell, Beckhoff, Omron, MQTT, MTConnect, BACnet, historian SQL, files and scales, among others. The connection goes out from the factory, stores and resends if the network drops, and no plant addresses or passwords ever leave it.
Result
Tested with 22 simulated machines: 106 out of 106 data points reach Sindri. If one machine goes down, the rest carry on. Not yet connected to a real factory.

Python · OPC UA · Modbus · Siemens S7 · MQTT · SQLite · Docker

For Grupo SPSIL · 2026

Real-time data gateway

Problem
The warehouse needed to see live stock from a website, but the databases sit on the internal network and no inbound ports could be opened.
What I did
A gateway in the style of the Power BI one: an agent inside the network opens a WebSocket tunnel to the website, queries MariaDB and SQL Server on demand and returns the data through that same tunnel.
Result
Up-to-the-minute stock on touch screens on the shop floor, permissions by department, an interface in Spanish, Chinese and English, and export to Excel.

Python · Django Channels · WebSocket · SQL Server · MariaDB
