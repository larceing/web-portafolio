Own product · 2026

Ticket, time and billing manager

Problem
Tickets were noted down by hand, hours lived in a spreadsheet and invoices somewhere else. Nothing was connected.
What I did
My own web application where each ticket carries its follow-up, its documentation, its timed work sessions and its billing. It uses MantisBT as the ticket engine through its API, without touching its code.
Result
History migrated and reconciled to the cent, a pro forma → invoice → payment cycle, transactional email and 181 automated tests that walk through every state change.

Node.js · MariaDB · REST API · Docker · Nginx

For Grupo SPSIL · 2026

Real-time data gateway

Problem
The warehouse needed to see live stock from a website, but the databases sit on the internal network and no inbound ports could be opened.
What I did
A gateway in the style of the Power BI one: an agent inside the network opens a WebSocket tunnel to the website, queries MariaDB and SQL Server on demand and returns the data through that same tunnel.
Result
Up-to-the-minute stock on touch screens on the shop floor, permissions by department, an interface in Spanish, Chinese and English, and export to Excel.

Python · Django Channels · WebSocket · SQL Server · MariaDB

Own product · in development

Appointment CRM with an offline tablet app

Problem
A business that manages patient appointments in hospitals was working with a spreadsheet-based application that had fallen short, and hospitals do not always have coverage.
What I did
I rewrote it as a web application with its own database and a tablet app that works offline: it saves locally, queues the changes and syncs them as versioned events when the network comes back.
Result
Schedule, patients, services, payments, documents and alerts in one place, with a conflict screen to decide when two devices change the same thing. Deployed on my own server.

Next.js · TypeScript · PostgreSQL · Prisma · React Native · Docker

For Grupo SPSIL · in development

AI assistant on top of the ERP

An assistant that answers business questions by querying the ERP in read-only mode. Each type of query is a closed function; the model chooses which one to use and with which parameters, so it does not make data up. It relies on editable business notes that explain how each figure is calculated, and it answers in text or in Excel.

Python · Agents · Knowledge base · SQL Server
