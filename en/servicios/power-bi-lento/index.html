Your Power BI report is slow: causes and fixes

You open the report and the charts keep loading, or every filter takes seconds. It is almost always one of these six causes. Start with Performance Analyzer in Power BI Desktop (Optimize ribbon): it tells you which visual is slow and where its time goes. If you can’t find it, I’ll go through it with you.

The six most common causes

For each one, the clue that gives it away and what to do. Performance Analyzer tells you where to start.

Cause 1

Too many visuals on one page

The page is slow to open and, in Performance Analyzer, many visuals spend time in “Other”: they are waiting for the rest to finish.

  • Keep only what is needed on each page.
  • Move the detail to a drillthrough page or a report page tooltip.
  • Test custom visuals one by one: a poorly built one slows down the whole report.

Cause 2

A table that shows everything

A table or matrix shows thousands of unfiltered rows, and it is the slowest item in Performance Analyzer.

  • Give it a Top N filter to limit the rows, with a maximum higher than anyone will look at.
  • Open the page with a sensible filter already set, such as the current month, instead of the whole history.

Cause 3

The model loads more data than it uses

The file is large, refresh is slow too and the whole report lags, not one particular visual.

  • Remove the columns and rows no report uses; for example, load only the last few years.
  • Turn off “Auto date/time”: it creates a hidden table for every date column.
  • Create new columns in Power Query rather than as DAX calculated columns.

Cause 4

Heavy DAX measures

In Performance Analyzer, the “DAX query” takes most of the time.

  • Store in a variable (VAR) whatever the measure calculates twice, so it is calculated only once.
  • Inside CALCULATE, use simple conditions on a column instead of FILTER over the whole table.
  • Copy the query from Performance Analyzer and test it in DAX query view until it gets faster.

Cause 5

Two-way relationships

In model view, a relationship has arrows in both directions.

  • Keep them single-direction unless they are needed: two-way ones give every query more work.
  • If it was so a slicer only shows options with data, filter the slicer with an “is not blank” measure instead.
  • If a measure needs to filter both ways, turn it on only in that measure with CROSSFILTER.

Cause 6

DirectQuery or a slow source

The data isn’t imported: every filter asks the database, and in Performance Analyzer “Direct query” takes the time.

  • Consider importing the data: it is Microsoft’s recommended default and it answers from memory.
  • If you need DirectQuery, keep measures simple (SUM, COUNT, MIN, MAX, AVERAGE) and avoid two-way relationships.
  • Keep the gateway and the database close to your Power BI region to cut latency.

Frequently asked questions

Why is my Power BI so slow?
Almost always for one of these reasons: too many visuals on the page, a model with more data than it needs, heavy DAX measures, two-way relationships or a slow source with DirectQuery. Performance Analyzer tells you which.
How do I know which visual is slow?
Open Performance Analyzer (Optimize ribbon in Power BI Desktop, or the View menu when editing the report in the service), select “Start recording” and then “Refresh visuals”. You’ll see how long each one takes and on what.
Is it better to import the data or use DirectQuery?
Import, unless you have a reason not to: the data is queried from memory and responds fast. With DirectQuery every visual asks the database, so it is only as fast as the database. It makes sense if you need near real-time data or it doesn’t fit in the model.
